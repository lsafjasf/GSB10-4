# 统计信息过期检测 —— 设计说明与实测数据

语言：Python 3（仅标准库）。文件：

- `staleness.py` —— 检测库（直方图、PSI、蓄水池采样、三路信号判定）
- `selftest.py` —— 自测：场景构造、重算对照、阈值扫描、性能测量、硬性断言
- `run_output.txt` —— 一次完整运行的原始输出

运行命令：

```bash
cd staleness_lab
python3 selftest.py        # 全部断言通过时退出码 0，否则 1
```

## 一、过期判断依据：三路信号如何权衡

核心观点：**只看时间会双向误判**（数据早变了时间没到 → 漏判；数据没变时间到了 → 误判），
所以时间只能当兜底，主判据必须是"数据本身变了多少"。

| 信号 | 度量 | 能抓住什么 | 抓不到什么 |
|---|---|---|---|
| 变更量 | `(ins+upd+del)/统计时行数` | 任何写入，成本为零 | 同分布换血（写了 60% 但分布没变）会误报 |
| 分布漂移 | 加权估计分布 vs 快照的 PSI | 统计信息真正关心的东西：分布 | 样本太少时不可用；行数纯增减不反映 |
| 时间 | `now - 统计时刻` | 计数器/采样都漏掉的缓慢泄漏、未跟踪写路径 | 一切——它只是代理变量 |

关键设计两点：

1. **漂移估计必须加权**。蓄水池里只有"新写入的值"，直接和快照比会把 10% 的
   写入放大成全表漂移（实测：10% 中等漂移的样本 PSI=3.54，真值只有 0.10）。
   按 `幸存旧行×快照分布 + 新行×样本分布` 加权后，估计 PSI=0.099 ≈ 真值 0.103。
2. **漂移证据可以否决变更量告警（veto）**。三路简单"或"逻辑下，同分布换血的
   150 张表被变更量信号全部误报（误判率 19.33%）；开启 veto 后：漂移信号可用
   且低于阈值时，仅当净行数变化超限才判过期——因为行数本身也是统计信息，
   而行数变化可以被计数器精确跟踪，不需要重算分布。

判定规则（`Detector.decide`）：

```
快照缺失                     -> UNKNOWN（显式无法判断，绝不默认新鲜）
age >= max_age               -> STALE（时间兜底，独立触发）
漂移可用且 PSI >= 阈值        -> STALE
漂移可用且 PSI < 阈值（veto） -> 仅 |净行数变化| >= 10% 才 STALE，否则 FRESH
漂移不可用（样本 < 30）       -> 回退变更量阈值 change_ratio >= 0.20
```

UNKNOWN 的表不计入误判/漏判，但计入"需要重算"——无法判断时必须重算确认，
不能默许其继续被优化器使用。

## 二、判定结果 vs 重算真值的对照

真值定义：对 100 万行全量重算统计，重算 PSI >= 0.10 或行数变化 >= 10% 即为
"真实过期"。默认阈值：`change_ratio>=0.2, PSI>=0.25, max_age>=100`。

| 场景 | 表数 | 真实过期 | FRESH | STALE | UNKNOWN | 误判 | 漏判 |
|---|---|---|---|---|---|---|---|
| 从未变更 | 400 | 0 | 400 | 0 | 0 | 0 | 0 |
| 微变（0.5% 同分布更新） | 200 | 0 | 200 | 0 | 0 | 0 | 0 |
| 同分布换血（60% 重写） | 150 | 0 | 150 | 0 | 0 | 0 | 0 |
| 中等漂移（10% 行偏移） | 50 | 24 | 50 | 0 | 0 | 0 | 24 |
| 剧变（40% 行大幅偏移） | 150 | 150 | 0 | 150 | 0 | 0 | 0 |
| 统计缺失 | 50 | — | 0 | 0 | 50 | 0 | 0 |

混淆矩阵（950 张可判定 + 50 张 UNKNOWN）：
**TP=150，FP(误判)=0，TN=776，FN(漏判)=24；误判率 0.00%，漏判率 13.79%，
需重算 200/1000 张。**

24 张漏判全部是"中等漂移"场景里真值 PSI 恰好落在 [0.10, 0.25) 区间的边界表
——这是阈值位置的取舍，把漂移阈值从 0.25 收紧到 0.10 后漏判降到 2 张
（漏判率 1.15%），见下表。

检测信号与重算真值抽样对照（每场景 1 张）：

| 场景 | change_ratio | 加权样本PSI | 年龄 | 重算PSI | 行变率 | 判定 |
|---|---|---|---|---|---|---|
| never | 0.000 | -- | 44 | 0.000 | 0.000 | FRESH |
| micro | 0.005 | -- | 24 | 0.000 | 0.000 | FRESH |
| churn | 0.600 | 0.018 | 41 | 0.009 | 0.000 | FRESH（veto 生效） |
| moderate | 0.100 | 0.099 | 10 | 0.103 | 0.000 | FRESH（边界漏判） |
| drastic | 0.800 | 1.844 | 37 | 1.800 | 0.000 | STALE |
| missing | -- | -- | -- | -- | -- | UNKNOWN |

## 三、阈值对比（误判率 / 漏判率 / 重算表数）

| 误判率 | 漏判率 | 重算表数 | 配置 |
|---|---|---|---|
| 44.72% | 0.57% | 570/1000 | 三路都严（change=0.05, PSI=0.10, age=30），时间主导误报 |
| 0.00% | 13.79% | 200/1000 | **默认**：change=0.2, PSI=0.25, age=100, veto 开 |
| 0.00% | 1.15% | 222/1000 | 漂移阈值收紧到 0.10（推荐生产值） |
| 0.00% | 13.79% | 200/1000 | 漂移阈值放宽到 0.50 |
| 19.33% | 13.79% | 350/1000 | 简单或逻辑（veto 关）：churn 场景 150 张全误报 |
| 25.90% | 74.14% | 296/1000 | 只信时间 max_age=40：双向爆炸 |
| 0.00% | 100.00% | 50/1000 | 只信时间 max_age=100：漏掉全部真实过期 |
| 19.33% | 13.79% | 350/1000 | 只信变更量 change=0.2 |

阈值设定依据：

- **PSI 0.10 / 0.25**：PSI 的经验解释界（<0.1 无显著变化，0.1~0.25 中度，
  >0.25 显著）。上表显示 0.10 是本数据集上漏判/重算的最佳平衡点
  （漏判 1.15%，仅多算 22 张表）；0.25 更省重算但放过边界漂移。
- **change_ratio 0.20**：借鉴 SQL Server 的 20% 自动更新阈值；在本方案中它
  只在样本不足时兜底，所以取保守值即可，veto 机制会拦住它的误报。
- **max_age**：纯兜底，应设得足够大（默认 100），让数据信号先说话——
  "只信时间"两行就是用户问题的量化证据：max_age=40 时误判 25.9% 且
  漏判 74.1%，max_age=100 时漏判 100%。
- **min_sample 30**：PSI 在 12 桶下每桶期望仅数样本即噪声主导，30 是
  统计上最低限度的样本量；不足时显式回退变更量，不硬猜。

## 四、性能：100 万行 / 1000 张表

| 指标 | 数值 |
|---|---|
| 全量重算 analyze 100 万行（对照成本） | ~75–91 ms |
| **增量检测 1000 张表** | **~5–8 ms（均摊 ~0.005–0.008 ms/表）** |
| 检测过程 Python 堆分配峰值（tracemalloc） | ~345 KiB |
| 每表常驻元数据（计数器 + 128 蓄水池 + 12 桶直方图） | ~1.8 KB/表，1000 表合计 ~1.75 MB |

检测不触碰 100 万行数据本身，只读每表 128 个采样值 + 计数器，因此耗时与
行数无关、只与表数线性相关；相比全量重算快约 1 万倍行级工作量，且 1000 张
表的元数据总量不到 2 MB。

## 五、覆盖情形与自测断言

`selftest.py` 末尾含硬性断言（失败退出码=1）：统计缺失→全 UNKNOWN、
从未变更→全 FRESH、微变→全 FRESH、同分布换血→全 FRESH（veto 生效）、
剧变→全 STALE、默认阈值误判=0、漏判=24（边界表）、UNKNOWN 不进混淆矩阵。
当前全部通过（见 `run_output.txt` 末节）。

已知边界（显式声明，不掩盖）：

- 真值 PSI 落在 [0.10, 0.25) 的边界表在默认阈值下会漏判，用阈值 0.10 可换
  到 1.15% 漏判率；这是阈值取舍，不是检测盲区。
- 纯 delete 不产生样本，delete 占比极高且分布随之改变时依赖变更量兜底与
  时间兜底。
- 写入值未经过 `record_write` 上报的表（旁路写入）只能靠 max_age 兜底，
  这是所有增量方案的共同前提。
