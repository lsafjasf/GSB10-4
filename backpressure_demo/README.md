# 流式背压反馈（Python 3 标准库，asyncio）

单生产者 / 单消费者的字节帧流。生产端比消费端快时，缓冲到达高水位即
**暂停**生产端；消费端把缓冲降到低水位才**恢复**。高/低水位构成迟滞带，
抑制水位抖动。纯标准库：`asyncio`、`collections.deque`。

## 文件

- `backpressure.py` — 库（`BackpressureStream`）
- `test_backpressure.py` — 自测：极慢消费 / 瞬时抖动 / 空流 / 单条超大消息 /
  对拍 / 内存上界
- `bench.py` — 100 万条消息基准：总耗时、暂停次数、缓冲峰值、RSS 采样
- `README.md` — 本说明

## 水位规则

缓冲占用按**字节数**计，帧不可拆分，先进先出。

| 事件 | 触发条件 | 位置 |
|---|---|---|
| 暂停 PAUSE | 一次 `write` 入队后 `buffered_bytes >= high_water` | `write()` 尾部同步判定 |
| 恢复 RESUME | 暂停状态下，一次 `read` 出队后 `buffered_bytes <= low_water` | `read()` 中判定 |

- 迟滞带：`low_water < buffered_bytes < high_water` 时**维持当前状态不变**，
  消费速度在单一阈值附近抖动不会反复翻转。
- 暂停时 `write()` 在 asyncio.Event 上挂起；恢复后被唤醒重试。
- `low_water == high_water` 即“无迟滞带”，测试中用于对照。
- 约束：`0 <= low_water <= high_water`。

## 不丢帧、不重复

所有帧只经过同一个 `deque`：恰好一次 `append` 对应恰好一次 `popleft`；
`close()` 只在缓冲排空后才让 `read()` 返回 EOF。自测对 500 帧断言输出与
源字节流逐字节相等（见对拍）。

## 内存上界证明

生产者在**入队前**检查暂停标志，而标志在越过高水位的那帧入队后
**同步**置位（中间无 `await`，无其他协程可插入）。因此越过
`high_water` 时最多多放入 1 帧：

```
peak_buffered_bytes < high_water + max_frame_size
```

与消息总条数无关。单帧超过 `high_water` 时不会拆分/丢弃，它单独通过，
上界退化为该帧自身大小（仍满足上式）。

## 运行命令

```bash
cd backpressure_demo
python3 -m unittest -v     # 自测（含对拍、内存、抖动、边界情形）
python3 bench.py           # 100 万帧基准
```

## 实测数据（Python 3.12.3，x86_64 Linux）

### 100 万帧基准（`bench.py`）

帧 128 B，总载荷 122.1 MiB；高水位 1 MiB，低水位 256 KiB；消费端让出
CPU 的频率约为生产端的 8 倍（模拟消费更慢）。

```
total time   : 0.58 s  (~1.7M frames/s)
pauses       : 142
resumes      : 142      （暂停与恢复一一配对）
peak buffered: 1,048,576 B  (理论上界 high+frame = 1,048,704 B，成立)
```

RSS 采样（每 10 万帧，单位 KiB）——流过 122 MiB 后 RSS 漂移为 0：

```
frames_read   buffered_B   RSS_KiB
    100,000      970,752     21,808
    200,000      737,280     21,812
    300,000      507,904     21,812
    400,000      278,528     21,812
    500,000      946,176     21,812
    600,000      716,800     21,812
    700,000      487,424     21,812
    800,000      327,680     21,812
    900,000      921,600     21,812
```

### 内存上界自测（20,000 帧 × 4 KiB = 80 MiB 流过）

缓冲峰值 `<= 65,536 + 4,096 B`（断言通过）；RSS 在 22,812–22,816 KiB，
漂移 4 KiB，与消息总量无关。

### 抖动抑制对拍（400 帧，消费速度每 40 帧在 0 / 2ms 间翻转）

| 配置 | 暂停次数 | 恢复次数 |
|---|---|---|
| 无迟滞带（low == high = 16 KiB） | 392 | 392 |
| 迟滞带（low = 4 KiB, high = 16 KiB） | **62** | **62** |

迟滞带把翻转次数压到约 1/6，输出内容均与源流一致。

### 字节对拍（500 帧 × 2 KiB）

背压管线输出 == 不限速管线（无界队列）输出 == 源字节流
（`1,024,000 B`，`assertEqual` 通过）。

### 边界情形

- **极慢消费**：300 帧，消费端每帧让出 CPU；全部帧恰好一次、保序交付，
  暂停/恢复配对，缓冲峰值 `< high + max_frame`。
- **空流**：0 帧、0 暂停、0 恢复，正常 EOF。
- **单条超大消息**：1 × 8 MiB 帧（高水位仅 64 KiB）完整通过，1 次暂停 /
  1 次恢复，缓冲峰值 `<= high + 8 MiB`。
