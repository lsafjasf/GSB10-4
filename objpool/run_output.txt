[1. 预热依据(与冷启动耗时挂钩)]
----------------------------------------------------------------
实测冷启动均耗 t_create = 0.574 ms/对象
预热公式: warmup = min(max_size, ceil(budget/t_create), ceil(qps*t_create*headroom))
       = min(512, ceil(0.050/0.000574), ceil(2000*0.000574*2.0)) = 3
预热实际耗时 = 1.7 ms (预算 50 ms 内: True)
若不预热，前 3 次请求将各付 ~0.57 ms 冷启动，共 ~2 ms 尾延迟

[2. 分代规则与各代数量随时间变化]
----------------------------------------------------------------
预热 min_idle=1, 晋升: reuse>=3->GEN1, reuse>=8->GEN2
回收 TTL: GEN0=0.4s GEN1=1.2s GEN2=3.0s

 t(s)  size  idle   G0   G1   G2 reclaimed
  0.0    12    12    0    6    6         0 热用后: 6xGEN2 + 6xGEN1
  0.5    12    12    0    6    6         0 
  1.3     6     6    0    0    6         6 
  3.3     1     1    0    0    1        11 
结论: GEN0 0.4s 先回收, GEN1 撑到 1.2s, GEN2 撑到 3.0s, 且 size 不会低于 min_idle

[4. 容量上界与超限行为]
----------------------------------------------------------------
overflow=discard  -> 拿到临时对象(归还即弃); 池规模 size=8 (上界 8, 永不越界: True), overflows=1
overflow=raise    -> PoolExhausted: pool at max_size and overflow='raise'; 池规模 size=8 (上界 8, 永不越界: True), overflows=1
overflow=block    -> PoolExhausted: block timeout waiting for an object; 池规模 size=8 (上界 8, 永不越界: True), overflows=1

[6. 预热不足 vs 预热过量]
----------------------------------------------------------------
预热不足: min_idle=   1 预热耗时=    0.6ms | 突发200次借还   117.9ms miss= 199 命中率=  0.50%
预热合理: min_idle= 201 预热耗时=  118.2ms | 突发200次借还     0.1ms miss=   0 命中率=100.00%
预热过量: min_idle= 256 预热耗时=  150.5ms | 突发200次借还     0.1ms miss=   0 命中率=100.00%
不足->突发全付冷启动(~117ms); 合理->突发全命中且预热只花~116ms; 过量->也全命中, 但预热多花~33ms 且多占 56*4KB 内存等回收

[7. 长期空闲的分代回收]
----------------------------------------------------------------
突发后闲置, min_idle=1, ttl=(G0:0.3, G1:0.6, G2:1.0)s
  t=0.00s size=  80 idle=  80 reclaimed=   0 gen=[60, 0, 20]
  t=0.35s size=  20 idle=  20 reclaimed=  60 gen=[0, 0, 20]
  t=0.70s size=  20 idle=  20 reclaimed=  60 gen=[0, 0, 20]
  t=1.20s size=   1 idle=   1 reclaimed=  79 gen=[0, 0, 1]
  t=1.70s size=   1 idle=   1 reclaimed=  79 gen=[0, 0, 1]
结论: 涨过水位的空闲对象按代际 TTL 逐级回收(G0先G2后), 降到 min_idle=1 保底不塌
