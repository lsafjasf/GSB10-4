# 放映顺序推导规则

## 核心原则：关系优先于编号

页的文件编号（`slides` 中的数字）**只**用于生成"按编号排序"的对照序列，
绝不参与放映顺序的推导。放映顺序完全由 `relations` 关系图决定。
编号与关系打架时，一律以关系为准，并在逐页对照中列出该页及原因。

## 推导算法（全程迭代，无递归）

1. **归一化**：页集合取 `slides`（缺省时取 `relations` 的全部键）。
   未出现在页集合中的引用目标即为悬空引用，不自动补全。
2. **起点**：取显式指定的 `start`；缺省时取"入度为 0 且编号最小"的页
   （自引用不计入入度，否则自环节点永远不会成为起点）。
3. **遍历**：从起点沿后继边迭代前进，每个节点只取**第一条有效边**
   （目标存在且非自身）。已访问节点不跳过，交给成环检测处理，
   保证环一定被指出而不是被悄悄绕开。
4. **终止条件**：遇到无有效后继（正常结束）或回到路径上的节点（成环，
   在入环处截断，绝不无限循环）。
5. **不可达页**：存在但不在主遍历路径上的页不进入放映序列，
   作为 `unreachable_slide` 异常报告，不静默丢弃、也不擅自追加到末尾。
6. **孤立环**：主遍历结束后，在不可达区域内继续迭代找环，
   环上全部节点都会被列出。

## 异常分类与修复建议

| 分类 | 判定 | 修复建议 |
| --- | --- | --- |
| `dangling_reference` 悬空引用 | 后继目标不在页集合中 | 删除该边 / 改指存在的页 / 补建缺失页 |
| `duplicate_reference` 重复引用 | 后继列表内重复，或一页被多个前驱引用 | 列表内只保留第一个；多前驱只保留链上先到达者 |
| `self_reference` 自引用 | 后继指向自身（1 节点自环） | 删除自引用边或改指真正的下一页 |
| `cycle` 关系成环 | 沿后继边回到路径上的节点 | 断开环上一条回边（如尾→首）即可线性化 |
| `unreachable_slide` 不可达页 | 从起点沿关系图不可达 | 补边接入主链，或确认后移除 |

所有异常都会给出具体节点和可执行的修复建议，没有任何一类被忽略。

## 复杂度与深度上界

- 时间复杂度 O(N + E)，N 为页数、E 为关系边数。
- **递归深度上界为 0**：全部遍历均为迭代实现，不消耗 Python 调用栈，
  与页数无关。`bench_500.py` 在 `sys.setrecursionlimit(80)` 下跑通
  500 页长链即为实证（若含递归必然 RecursionError）。
- 实测 500 页（编号随机打乱）解析耗时约 **0.5–0.9 ms**，
  遍历链最长步数 500，详见 `reports/bench_500.txt`。

## 逐页对照

`analyze()` 同时输出 `numbered_order`（按编号排序）与 `order`（关系图推导），
并对每一页给出对照行：位置一致标记 `match`；不一致标记 `mismatch` 并附原因
（关系边覆盖编号 / 位于环上 / 不可达 / 被异常边截断）。
