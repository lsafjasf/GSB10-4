# 分块规则（语句边界判定规范）

分块器 `sqlchunk.lexer.split_statements` 对脚本做**单遍字节扫描**（O(n)），
状态机只有 7 个状态：普通、单引号串、双引号串、反引号、行注释、块注释、
美元引用串。所有判定字符均为 ASCII，多字节 UTF-8 内容原样透传。

## 语句终结符

- 默认终结符为 `;`。
- 行首（允许前导空格/制表符）出现 `DELIMITER <str>` 指令行时，终结符切换为
  `<str>`（MySQL 客户端语法，用于存储过程/触发器）。指令行本身被消费，
  不进入任何语句、不参与执行。
- 脚本末尾没有终结符的剩余片段：若含任何非空白字符，仍作为一条语句
  （缺终结符的语法错误交给执行引擎报告，切分器保持无损）；纯空白则丢弃。

## 以下构造内部的分隔符一律不断开语句

| 构造 | 起始 | 结束 | 转义/特例 |
|---|---|---|---|
| 单引号字符串 | `'` | `'` | `''` 双写、反斜杠 `\'`（MySQL 规则） |
| 双引号字符串/标识符 | `"` | `"` | `""` 双写、反斜杠 `\"` |
| 反引号标识符 | `` ` `` | `` ` `` | 无转义 |
| 行注释 | `--` 后必须跟空白/行尾；`#` | 换行 | `--1` 不视为注释（与 MySQL 一致） |
| 块注释 | `/*` | `*/` | 不嵌套 |
| 美元引用串 | `$tag$`（tag 可为空） | 相同的 `$tag$` | PostgreSQL 风格 |
| 反斜杠续行 | `\` + 换行 | — | 普通状态下反斜杠是普通字符，续行对原样保留在语句内，永不成为切分点 |

未闭合的字符串/注释不会导致切分器崩溃：剩余内容归入最后一条语句，
语法错误在执行阶段暴露。

## 分块（chunk）规则

- 语句按顺序贪心装填：加入下一条语句会超过 `max_chunk_bytes` 时封块。
- **单条语句超过上限时独占一块**并标记 `oversized: true`——语句完整性
  永远优先于体积上限。
- 块的执行文本 = 块内各语句切片的顺序拼接；空语句、纯注释语句保留在
  切片中（保持偏移可校验），执行时跳过。
- 每块记录：`index`、`start_stmt`/`end_stmt`（语句序号区间）、
  `byte_start`/`byte_end`（源脚本字节偏移）、`sha256`（块文本哈希）、
  `statements`、`bytes`、`oversized`。

## 方言说明

切分器是方言超集（同时容忍 MySQL/PostgreSQL/SQLite 的引用与注释形式），
但**执行引擎是可插拔的**：自带的 `make_sqlite_executor` 用标准库
`sqlite3` 执行，脚本须为 SQLite 可执行的 SQL（例如 SQLite 不支持
`$$` 美元引用与 `\` 字符串转义）。对接 MySQL 时把 `run_chunk` 换成对应
驱动即可，切分与断点逻辑不变。
